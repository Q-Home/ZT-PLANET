# Windows client installation

This guide connects a Windows PC or Windows Server to the existing Q-Home
ZeroTier network using the standard ZeroTier One client and Q-Home Moon file.
This guide covers client installation only; it does not change the central server deployment.

## Prerequisites

- A Windows release supported by the current ZeroTier One installer.
- Local administrator rights and Windows PowerShell 5.1 or PowerShell 7.
- The Q-Home server already deployed using the [deployment guide](deployment.md).
- The 16-character hexadecimal network ID from **Q-Home ZTNET**.
- The exact `.moon` filename generated by `scripts/generate-planet.sh`.
- HTTPS access to `https://zt.q-home.be` and UDP connectivity to the Moon's
  public endpoint (normally UDP 9993).

The filename `0000009445e68ada.moon` below is an example from the Linux guide.
Confirm the actual filename on the server under `data/public/qbox/`.
The Moon ID, network ID and Windows node ID are different identifiers.

## 1. Install ZeroTier One

Download the Windows MSI from the [official ZeroTier download page](https://www.zerotier.com/download/)
and install it as administrator. Keep the default service and network driver.
You do not need Docker, WSL or Git for the Windows client.

Open **PowerShell as administrator**. Reopen it after installation so the
updated PATH is loaded. Run all following PowerShell blocks in that same window.

```powershell
$ErrorActionPreference = 'Stop'
Get-Service -Name ZeroTierOneService
Start-Service -Name ZeroTierOneService

$ZtCommand = Get-Command zerotier-cli -ErrorAction SilentlyContinue
if (-not $ZtCommand) {
    throw 'ZeroTier CLI not found. Reopen PowerShell or locate zerotier-cli.bat in the ZeroTier installation folder.'
}
$ZtCli = $ZtCommand.Source
& $ZtCli info
if ($LASTEXITCODE -ne 0) { throw 'Cannot communicate with the ZeroTier service.' }
```

If the CLI is not in PATH, set `$ZtCli` to the installed `zerotier-cli.bat`
and rerun the `info` command. A common installation path is:

```powershell
$ZtCli = 'C:\Program Files (x86)\ZeroTier\One\zerotier-cli.bat'
if (-not (Test-Path -LiteralPath $ZtCli)) { throw 'Check the actual ZeroTier installation folder.' }
& $ZtCli info
```

The output contains the Windows device's 10-character node ID. Record it for
authorization in ZTNET. `ONLINE` means root infrastructure is reachable; it does
not yet prove that the Q-Home network or Moon works.

## 2. Install the Q-Home Moon file

Windows uses `%ProgramData%\ZeroTier\One` as its service data directory, normally
`C:\ProgramData\ZeroTier\One`. The Moon file belongs in its `moons.d` subfolder,
not in the installation folder under Program Files.

Set the actual hostname and generated Moon filename, then run:

```powershell
$ZtDomain = 'zt.q-home.be'
$MoonFile = '0000009445e68ada.moon' # Replace with the server's actual filename
if ($MoonFile -notmatch '^[0-9a-fA-F]{16}\.moon$') { throw 'Invalid Moon filename.' }

$MoonDir = Join-Path $env:ProgramData 'ZeroTier\One\moons.d'
$MoonPath = Join-Path $MoonDir $MoonFile
New-Item -ItemType Directory -Path $MoonDir -Force | Out-Null

# Download to a temporary file first, so a failed download preserves any existing Moon.
$MoonTemp = Join-Path $MoonDir ($MoonFile + '.download')
try {
    Invoke-WebRequest -UseBasicParsing -Uri "https://$ZtDomain/qbox/$MoonFile" -OutFile $MoonTemp
    if ((Get-Item -LiteralPath $MoonTemp).Length -eq 0) { throw 'Downloaded Moon file is empty.' }
    Move-Item -LiteralPath $MoonTemp -Destination $MoonPath -Force
} finally {
    if (Test-Path -LiteralPath $MoonTemp) { Remove-Item -LiteralPath $MoonTemp -Force }
}

Restart-Service -Name ZeroTierOneService
Start-Sleep -Seconds 20
& $ZtCli listmoons
```

Use the binary `.moon` file produced by the server. Do not save `moon.json` or
an HTML page as a `.moon` file. Keep the normal Windows directory permissions.
Confirm that the expected Moon appears in `listmoons`; the non-empty download
check alone does not validate the Moon contents. Keep the standard `planet` file.

Restarting ZeroTier interrupts existing ZeroTier connections briefly. If your
only remote access is through ZeroTier, perform this step with local access or
an alternative management connection available.

## 3. Join the Q-Home network

```powershell
$NetworkId = Read-Host 'Enter the Q-Home network ID from ZTNET'
if ($NetworkId -notmatch '^[0-9a-fA-F]{16}$') { throw 'Network ID must contain 16 hexadecimal characters.' }

& $ZtCli join $NetworkId
if ($LASTEXITCODE -ne 0) { throw 'Network join command failed.' }
& $ZtCli info
& $ZtCli listnetworks
```

`200 join OK` means the join request was accepted locally. The device may still
show `ACCESS_DENIED` until it is authorized.

1. Open `https://zt.q-home.be` and sign in to Q-Home ZTNET.
2. Open the network matching `$NetworkId`.
3. Find the member matching the Windows node ID from `info`.
4. Give it a recognizable name, such as `office-remko-laptop`, and authorize it.
5. Confirm that the network has an appropriate managed IP assignment/pool.

Use the self-hosted **ZTNET**, rather than ZeroTier Central, for this network.
The Linux `/qbox/install-moon.sh` installer is not a Windows installer: its
hostname/eth0 serial logic and metadata callback do not run in this procedure.
Register any required customer/project metadata separately.

## 4. Validate the deployment

```powershell
& $ZtCli info
& $ZtCli listmoons
& $ZtCli listpeers
& $ZtCli listnetworks
Get-NetAdapter | Where-Object { $_.InterfaceDescription -like '*ZeroTier*' }
```

Check each result:

| Check | Expected result |
| --- | --- |
| `info` | Correct node ID and `ONLINE` |
| `listmoons` | The Q-Home Moon is present |
| `listpeers` | The configured Moon root becomes reachable; it may take time to appear |
| `listnetworks` | Correct network ID, status `OK` and an assigned ZeroTier IP |
| Application connection | A known service on another authorized member is reachable |

Public `PLANET` peers remain normal: the architecture retains public bootstrap
and fallback. Seeing a Moon in `listmoons` confirms configuration, not a working
UDP path to that root.

Test a real service using another member's **ZeroTier IP**, for example RDP on
a Windows host where RDP is enabled and permitted:

```powershell
$PeerZtIp = Read-Host 'Enter the peer ZeroTier IP'
Test-NetConnection -ComputerName $PeerZtIp -Port 3389
```

Use the actual application port if it is not RDP. A failed ping alone does not
prove a ZeroTier failure: ICMP can be blocked by the receiving host.

## 5. Firewall and network access

Allow the ZeroTier application's UDP traffic according to your firewall policy.
The client needs to reach the Moon on its published UDP port (normally 9993);
direct peer communication can also use other UDP ports. HTTPS 443 is needed to
download the Moon file. TCP `Test-NetConnection -Port 9993` is not a UDP test.

A normal Windows client does not need public port forwarding for 80, 443 or 9993.
Those public inbound server ports belong to the central deployment. Keep Windows
Firewall enabled and scope application rules (RDP, file sharing, etc.) to the
intended ZeroTier peers/subnet. Network authorization does not automatically
enable those Windows services or their firewall rules.

## 6. Updates and removal

Update the client with the official installer, then repeat the validation steps.
When Q-Home publishes a changed Moon file, repeat step 2 with the correct filename.
If replacing a Moon with a different ID, remove the retired Moon only after the
new one has been verified.

To disconnect this Windows device from the network:

```powershell
& $ZtCli leave $NetworkId
```

Also revoke its authorization in ZTNET when decommissioning the device. To remove
the downloaded Moon file, remove only that specific file and restart the service:

```powershell
Remove-Item -LiteralPath $MoonPath
Restart-Service -Name ZeroTierOneService
& $ZtCli listmoons
```

These commands assume the variables from the earlier steps are still defined.
Do not copy `identity.secret` or `authtoken.secret` to other machines. Each
Windows device needs its own identity and authorization.

## Troubleshooting

| Symptom | Action |
| --- | --- |
| CLI not found | Reopen PowerShell; locate the installed `zerotier-cli.bat` and set `$ZtCli` to its full path |
| Authentication token unreadable | Run PowerShell as administrator; do not change token permissions to make it public |
| Cannot connect to service | Check `Get-Service ZeroTierOneService` and start the service |
| Moon download returns 404 | Confirm hostname, exact filename and publication under `data/public/qbox/` on the server |
| HTTPS/certificate error | Check system time, DNS and the server certificate; do not bypass certificate validation |
| Moon absent from `listmoons` | Check `%ProgramData%\ZeroTier\One\moons.d`, file contents and service restart |
| Moon configured but unreachable | Check the Moon's published public IP/UDP port, server firewall/NAT and client UDP policy |
| `ACCESS_DENIED` | Authorize the exact node ID in the correct Q-Home ZTNET network |
| `REQUESTING_CONFIGURATION` persists | Verify network ID, controller availability and UDP connectivity |
| `NOT_FOUND` | Verify that the network exists on the self-hosted controller and that its ID is correct |
| `PORT_ERROR` | Inspect the ZeroTier virtual adapter/driver and consult the official Windows troubleshooting guide |
| Network `OK`, service unreachable | Check peer authorization, managed IPs/routes, application listener and receiving Windows Firewall rules |
